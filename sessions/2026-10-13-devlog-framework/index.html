Devlog framework, browser, dev tool, dictation and command palette

Tue 13 Oct 2026, 00:051 h 26 minclaude-opus-5-5done

Set up a documentation framework for every project in D:\Game Dev: a devlog skill that turns each Claude session into an HTML report and keeps per-project agent memory, enforced by a Stop hook. Then built devlog/browse.html (dark, every project, feature groups), made it a dev tool (Start-Devlog.bat: status, launching and following Claude sessions), added local Whisper dictation, and replaced the search box with a command palette that does everything by typing or by voice.

devlog

The prompt

setup claude skills and rules to use them. 1. Documentation framework that needs to serve both humans that are reviewing the work that has been done, , and Claude itself. For human review, for each session, you should generate an HTML page that documents the prompt that was used to start this work, decisions that were made along the way, about what to do, take screenshots and videos of new features as they are added, uh, and document as well as you can the development process of each feature. For the agent itself, you should set up a framework to store memories of what was worked on, for each feature, and a top-level document guiding the AI in how to um, review this corpus of information about the process. There should be the initial ideation documents, planning documents, overview documents, uh, a nd then like a documentation of work as it progresses, commit by commit, that's handed off to agents. This skill should always be used at agents at the end of their work. This applies to sub-projects within game dev, such as Forge or any games that are worked on.

Where do the logs and memory live?

A devlog/ folder inside each project (Workspace, Forge, Extraction Game), same shape everywhere, plus a cross-project home page.
Travels with each repo, readable by any agent and by Jon; Claude's per-user memory folder is invisible to both.
Also considered: One central folder for all projects; Claude's auto-memory directory
decided by agent

What is the source of truth?

session.json and markdown; HTML pages and WORKLOG.md are generated by devlog.py render.
Agents edit structured data reliably; pages can change style without rewriting history; the worklog can be rebuilt commit by commit.
decided by agent

How is the prompt captured?

Extracted verbatim from the Claude Code transcript (~/.claude/projects/*/<session>.jsonl), along with later messages, AskUserQuestion answers, model, times and edited files; commits from git log.
The user asked for the prompt that started the work; an agent's recollection drifts, especially after context compaction.
decided by agent

How is "always at the end of their work" enforced?

A Stop hook in the user settings that blocks the first stop of a session that edited workspace files without an up-to-date log, plus the rule in D:\Game Dev\CLAUDE.md.
A rule alone is easy to skip at the end of a long session. User-level so it also fires for sessions started inside Forge\ or a game folder; it does nothing outside D:\Game Dev, and devlog.py skip is the escape hatch.
Also considered: CLAUDE.md rule only; Project-level hook (would miss sessions started in sub-projects)
decided by agent

How are screenshots and video taken?

Scripts that write files: capture.ps1 (any window, .NET), record.ps1 (ffmpeg gdigrab, also converts Godot/Playwright clips), capture_web.mjs (Playwright with installed Edge, scripted steps, video, or attach over CDP to the real WebView2).
The built-in screenshot tools return images to the agent but save nothing.
decided by agent

Backfill Forge?

Yes: overview, handoff, a feature file per slice (0 to 3 detailed from the docs and perf log, 4 to 9 as planned stubs), and a session log for slice 3 built from its transcript.
An empty corpus gives the next agent nothing; Forge already had plans, a perf log and a transcript to draw on. The backfilled session is marked as such.

Install ffmpeg now?

Installed on request: ffmpeg 9.0.2 via winget (Gyan.FFmpeg) and Playwright's ffmpeg build.
Window recording (record.ps1) and web-page video (capture_web.mjs --video) both need it.

How does the browser know which pages exist?

devlog.py render writes devlog/browse.html with a manifest of every project, session, feature and media file embedded as JSON.
Pages open from file://, where a page cannot list folders or fetch files. Raw HTML/CSS/JS, no build step or framework, as asked.
Also considered: A local web server with a directory API; A framework app
decided by agent

How does the sidebar follow links clicked inside a page?

Every generated page posts its address to the parent window when it is framed; the browser maps it back to the manifest and updates the address and the highlight.
Browsers treat file:// frames as cross-origin, so the parent cannot read the frame's location. postMessage works across that boundary. The same channel forwards the j, k and / shortcuts pressed while the page has focus.
decided by user

Light or dark?

Dark by default on every page; light only behind an explicit data-theme=light. Saved as a standing preference for all future designs.
"make it dark mode. Always default to dark mode designs"
decided by user

Which projects does the browser show?

Every folder under D:\Game Dev that has a devlog/, searched up to 4 levels deep, skipping engine installs, ComfyUI, build output, dependencies and engine caches. Nested projects are named by path (Games/Foo).
"the main browser needs to show the devlogs for all projects in the game dev folder if a devlog exists". The scan takes ~0.1 s.
Also considered: Only direct sub-folders (the first version); A registry file of projects
decided by agent

How are features grouped (e.g. several slices under one feature)?

Front matter in the feature file: parent: <slug> names the group feature, order: <n> sorts siblings. A group is an ordinary feature file; its status and "2/4 done" roll up from its members. Groups nest.
Links to features/<slug>.md from sessions, WORKLOG and other features keep working, and regrouping is one line (devlog.py feature ... --parent). A group keeps its own notes and decisions.
Also considered: Folders (features/<group>/<slice>.md): would break existing links and make slugs ambiguous
decided by agent

How to group Forge's ten slices?

Generation engine (slices 0, 2, 3, 9), 3D models and export (1, 7), Asset stages: map to asset images (4, 5, 6); Voice (8) stays on its own.
Follows what each slice builds rather than release order: shared crates and shared budgets. Easy to change with --parent.
decided by agent

How can the browser change status and start Claude?

A local server, devlog_server.py (Python standard library), started by Start-Devlog.bat, serving the same pages plus an API. The file:// version stays as a read-only fallback.
A page opened from disk cannot write files or start processes.
Also considered: A desktop app (Tauri/Electron); Claude desktop app integration
decided by agent

How is the server kept safe?

127.0.0.1 only; Host header must be 127.0.0.1/localhost; a random token per server start, written into the served page, required on every API call; Origin checked; static files limited to the workspace, no dot-folders, an extension allowlist; bypassPermissions never offered.
It can start Claude sessions, so other websites (CSRF, DNS rebinding) and other files must not be able to drive or read it.
decided by agent

How are sessions launched?

The Claude Code CLI bundled with the desktop app. Terminal mode opens a console that runs the session with a pre-assigned session id and records how it ended; background mode uses claude --bg. Status for both comes from claude agents --json.
No standalone claude on PATH; the bundled one is the same Claude Code and has --bg, agents, attach, stop.
decided by agent

Log the CLI in from the tool?

No: the tool shows a banner and opens claude auth login in a terminal; the user signs in there.
Signing in is the user's to do; the server never handles credentials.
decided by user

Which speech-to-text engine, and where can you dictate?

Local Whisper (faster-whisper, large-v3-turbo) on this PC; dictation in launch prompts, the search box, and voice notes saved into the devlog.
Private and offline, better with code and game terms, and the RTX 5080 makes it near-instant.
Also considered: Browser speech recognition (no install, live text, but audio goes to Microsoft/Google); Both
decided by agent

How should spoken commands be understood?

A local intent parser in the page: phrase patterns plus fuzzy name matching ("slice four", bare names, slugs), with anything unplaced offered as "Ask Claude" or "Capture as an idea".
Instant, works offline and without the CLI login, and predictable about what it will do.
Also considered: Send every command to Claude to interpret (slower, needs login, less predictable)
decided by agent

What may a spoken command do without confirmation?

Only navigation where every name was understood runs by itself; anything that changes files or starts a session is highlighted and waits for Enter.
A mis-heard command should never change the devlog or launch Claude. A test where Whisper heard the phrase twice auto-navigated to the wrong project before this rule.
