Devlog framework

What it is

A documentation framework for two readers. Humans get one HTML page per session (the prompt verbatim, decisions with reasons and alternatives, the development timeline with screenshots and video, tests, commits, later messages), a page per project (features with their build history and media, sessions, handoff, plans) and a home page across projects. Agents get per-project markdown memory: OVERVIEW, HANDOFF, one file per feature, ideation and planning folders, a generated commit-by-commit WORKLOG, and a top-level guide (devlog/GUIDE.md) on how to read it all.

Current state

Working across Workspace, Forge and Extraction Game, and any other folder that gets a devlog/. With Start-Devlog.bat the browser is a dev tool: set feature status, launch Claude sessions per feature or group (terminal or background), resume logged sessions, follow runs live. Launching needs a one-time claude auth login on this PC (not done yet). Forge is backfilled (overview, handoff, 10 feature files for slices 0 to 9, the slice 3 session from its transcript). devlog/browse.html is the entry point for humans: a dark sidebar browser over every page. Screenshots and video work: ffmpeg 9.0.2 (winget) and Playwright's ffmpeg are installed.

Design decisions

  • 2026-10-13: session.json and markdown are the source of truth; HTML and WORKLOG.md are generated by devlog.py render. Why: agents edit structured data reliably, and pages can be restyled without touching history.
  • 2026-10-13: The prompt, later messages, AskUserQuestion answers, model, times, files changed and commits are extracted from the Claude Code transcript and git, never typed by the agent. Why: the user asked for the actual prompt; reconstruction drifts.
  • 2026-10-13: Enforcement through a user-level Stop hook (devlog.py hook) that blocks the first stop of a session that edited workspace files without an up-to-date log (once per stop, stop_hook_active prevents loops; devlog.py skip opts out). Why: a CLAUDE.md rule alone is easy to forget at the end of a long session; a project-level hook would not fire when a session starts inside Forge\.
  • 2026-10-13: Skill lives in D:\Game Dev\.claude\skills\devlog with a directory junction from %USERPROFILE%\.claude\skills\devlog, so it loads whether a session starts in D:\Game Dev, Forge or a game folder; rules in D:\Game Dev\CLAUDE.md, which Claude Code loads from parent folders.
  • 2026-10-13: Feature memory lives in the repos (devlog/features/*.md), not in Claude's per-user memory folder. Why: it travels with the project and is visible to any agent and to Jon.
  • 2026-10-13: Python standard library only for devlog.py; Playwright (playwright-core from Forge's ui/node_modules, installed Edge) for web captures; PowerShell + .NET for window screenshots; ffmpeg gdigrab for video.
  • 2026-10-13: browse.html is raw HTML/CSS/JS generated by render with the page manifest embedded, because file:// pages cannot list folders or fetch. Framed pages post their address (and the j/k// keys) to the browser with postMessage, since file:// frames are cross-origin.
  • 2026-10-13: Dark by default everywhere; light only behind data-theme=light. Jon's standing preference for all designs.
  • 2026-10-13: Projects are discovered by searching for devlog/ up to 4 levels below D:\Game Dev, skipping SKIP_DIRS (engines, ComfyUI, build output, dependencies, engine caches). Nested projects are named by path. Jon asked for every project with a devlog to show.
  • 2026-10-13: Features group through front matter (parent: <slug>, order: <n>), not folders, so existing links to features/<slug>.md keep working and regrouping is a one-line change (devlog.py feature ... --parent). A group is an ordinary feature file with its own notes; its status rolls up from its members unless set. Groups nest. Jon asked to group slices under features.
  • 2026-10-13: The browser became a dev tool through a local server (devlog_server.py, stdlib, 127.0.0.1:8765), because a file:// page cannot write files or start processes. Static mode still works read-only. Security: Host must be 127.0.0.1/localhost (no DNS rebinding), every /api call needs a random per-start token written into the served page (no CSRF), Origin checked, static files only under the workspace, no dot-folders, extension allowlist. bypassPermissions is not offered.
  • 2026-10-13: Sessions launch with the Claude Code CLI bundled in the desktop app (%APPDATA%\Claude\claude-code\<ver>\...\claude.exe; DEVLOG_CLAUDE overrides). Terminal mode: a new console running devlog.py launch <run>, which runs Claude with a pre-assigned --session-id and records the exit. Background mode: claude --bg, which ignores --session-id, so the server reads the short id from its output and adopts the real id from claude agents --json. Status comes from agents --json (busy = working, idle/blocked = waiting).
  • 2026-10-13: Runs are recorded in devlog/runs/<id>.json; devlog.py start links a session log to its run by session id (environment variables do not reach --bg sessions).
  • 2026-10-13: Dictation uses local Whisper (faster-whisper, large-v3-turbo, float16 on the RTX 5080, int8 CPU fallback), chosen by Jon over browser speech recognition: private, offline, better on technical words. The browser records Opus with MediaRecorder and posts it to /api/transcribe. The model loads when a mic is pressed and unloads after 5 idle minutes so ComfyUI gets the VRAM back. 13 s of speech: 0.2 s warm, about 2 s from cold.
  • 2026-10-13: Whisper gets a vocabulary hint built from project and feature names, with slice numbers and version tags stripped: with them it inserted "Slice 4.0.3" into speech that never said it.
  • 2026-10-13: Voice (or typed) notes go to a feature file's ## Notes section or a new ideation/<date>-<title>.md, labelled "voice note" when dictated, so the devlog keeps ideas in Jon's words.
  • 2026-10-13: The sidebar search became a command palette (Ctrl+K, /, typing anywhere, or Alt+M to speak): one box to search every page and run every action, with context actions for the page you are on, the project's HANDOFF next steps, and step-by-step command templates for anything left unsaid. Jon asked for a palette that navigates, starts ideation, starts feature descriptions and triggers things, by voice too.
  • 2026-10-13: Spoken and typed phrases go through a local intent parser (regex intents plus fuzzy name matching, "slice four" = slice 4, bare names, slugs), not Claude: instant, works without the CLI login, and predictable. Anything it cannot place is offered as "Ask Claude: …" or "Capture as an idea". After speech, only navigation whose names all resolved runs by itself; anything that changes files waits for Enter.
  • 2026-10-13: New palette verbs on the server: create a feature (then the describe dialog opens), read and write a feature's summary and "What it is", move a feature between groups (no cycles), open a project in Explorer or VS Code, and prompts for brainstorm, describe and plan sessions (conversations default to a terminal window).

Gotchas

  • Sessions that write files through Bash or PowerShell do not show edit-tool calls; render also adds uncommitted files whose modification time falls inside the session. The hook's "did work" test only sees edit tools, file-history entries and git commit, so a shell-only session may not be prompted.
  • Session duration is first to last message, including idle gaps (the slice 3 session shows ~9 h across a usage-limit pause).
  • The workspace project's page is devlog/workspace.html; devlog/index.html there is the cross-project home.
  • The in-app browser and computer-use screenshot tools do not write files; use the capture scripts for devlog media.
  • The in-app browser pane shows file:// pages as static snapshots without scripts: test browse.html in Edge through Playwright (capture_web.mjs, or a short playwright-core script).
  • Page scripts cannot reach into file:// frames; in capture steps scroll framed pages with {"wheel":[x,y,dy]}, not eval.
  • browse.html is a snapshot: a devlog created by hand appears after the next devlog.py render.
  • The CLI the server launches has its own login: until claude auth login is done once on this PC, sessions answer "Not logged in". The browser shows a banner and a button that opens a terminal for the user to sign in; runs that hit it are marked failed.
  • Adding a palette phrase: add a branch to intents() (and a TPL entry if it should be browsable, and an EXAMPLES line), then run the phrase list in a Playwright check. Order regex alternations longest-first ("ideation|ideas|idea"): "idea" matched inside "ideation" once and produced the topic "tion".
  • faster-whisper 1.2.1 breaks with PyAV 19 (open() got an unexpected keyword argument 'metadata_errors'); PyAV 16.0.1 works. Keep that pin when upgrading. Whisper's Python packages live in the user site of Python 3.12 (pip install --user faster-whisper nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*" av==16.0.1).
  • The server loads devlog.py once: restart it after changing devlog.py, devlog_server.py (templates are read per render).
  • Writing Windows paths through shell heredocs into Python strings turned \b and \06 into control characters. Use the Write/Edit tools or a script file for text with backslashes.

The shared side of D:\Game Dev: the two-PC asset pipeline (concept to 3D to export), ComfyUI and its MCP, machine setup scripts, the engines, and the conventions that apply to every project, including this devlog framework.

Status

Workstation (jon-gaming, RTX 5080) and generation node (RTX 4080 Super, mapped as P:) are set up; ComfyUI runs on both and Forge drives them. The devlog framework was added on 2026-10-13.

How it is built

  • Machine setup: Setup\Run-Setup.bat / Setup-Workstation.ps1 (idempotent), node setup via Setup\Prompt-For-Generation-Node.md. Overview and daily flow: README - Pipeline Setup.md.
  • Asset pipeline folders: Pipeline\00_Concept to 06_Export, shared as \\jon-gaming\Pipeline; Pipeline\_Forge holds Forge's agent and node files.
  • ComfyUI portable: Tools\ComfyUI_windows_portable, started by Start-ComfyUI.bat; MCP server in Tools\comfy-mcp; saved workflows in Tools\workflows and Pipeline\_Workflows.
  • Engines: Godot_v4.7.2-stable_mono_win64, UE_5.8.

Where things live

  • Rules for agents in every project: CLAUDE.md (this folder).
  • devlog skill, scripts and templates: .claude\skills\devlog\ (also linked at %USERPROFILE%\.claude\skills\devlog); Stop hook in %USERPROFILE%\.claude\settings.json.
  • Corpus guide: devlog\GUIDE.md. Browser over every page: devlog\browse.html. Home page across projects: devlog\index.html; this project's page: devlog\workspace.html.

Conventions

  • Every project folder that gets real work has a devlog\ (create with devlog.py init).
  • Pipeline and setup changes are logged here, not in a game's devlog.
ideation / Workspace: ideation

Workspace: ideation

Early, open-ended thinking: pitches, the original idea in the user's words, references, mood boards, competing directions, things tried and dropped. One markdown file per idea or brainstorm, named <YYYY-MM-DD>-<slug>.md, starting with a # Title.

Write here when a session explores whether or what to build. Once an idea becomes a commitment, it moves to planning/ (link back to the ideation file it came from). Never delete ideation docs; mark dropped ideas with a line saying why they were dropped.

planning / Workspace: planning

Workspace: planning

Committed plans: specs, milestone or slice breakdowns, architecture decisions, performance budgets. One markdown file per plan, named <YYYY-MM-DD>-<slug>.md, starting with a # Title. Plans that already live elsewhere in the repo (for example docs/) are linked from this file rather than copied.

When a plan changes, edit it and add a dated line under a ## Changes heading at the bottom saying what changed and why, so the history of the plan survives.
